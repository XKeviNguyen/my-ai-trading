## 2. Findings

Severity is about *this product's* requirements (PRD v1.1), not the starter's own stated scope. "Probe" means reproduced by a script; "Read" means found by reading the code.

### High — must fix before relying on the output

| # | Area | Finding | Evidence |
|---|---|---|---|
| H1 | Data/Correctness | **Bar-close boundary and clock skew.** `closed_candles` keeps a bar when `close_time_ms <= now_ms`, but Binance `closeTime` is the last millisecond *inside* the bar, so the bar is treated as closed 1 ms early. The bigger issue is that `now_ms` is the local clock with no server-time sync or safety margin: a local clock running ahead turns a forming candle into a "closed" one. | Probe P1; `candles.py:57` |
| H2 | Data | **Gaps not detected.** Missing bars (exchange downtime, delisting pauses) pass silently and indicators span the gap as if contiguous. PRD F01 requires gap detection. | Probe P2 (5 missing daily bars → `status: ok`) |
| H3 | Data/Timeframe | **Interval identity not enforced.** `analyze()` trusts the `interval` label and never checks bar spacing, so daily bars labelled `1w`/`1h` give `status: ok`. The V0.1 test `test_weekly_doesnt_pretend_daily_heuristic` itself passes daily fixtures as `1w`. This directly undermines PRD F03/F13 and Scenario L. | Probe P3 |
| H4 | Strategy fidelity | **Preset applied without selection.** The Minervini-inspired heuristic runs on every `1d` analysis regardless of user choice. This breaks F04 "users can turn all profiles off" and Scenario B. | `analysis.py:50,63` |
| H5 | Strategy fidelity | **Overstated `pass`.** The trend heuristic evaluates 5 criteria and omits relative strength among others, yet reports `status: "pass"`. That reads as a satisfied trend template. It should be `partial`, with the unevaluated criteria listed. | Probe P5 |
| H6 | Architecture | **No F13 metadata.** Profiles have no `timeframe_policy`, mode, provenance, evidence level or maturity enum, and the output has no applicability status. Every R3 gate depends on these. | `profiles.py` |

### Medium

| # | Area | Finding | Evidence |
|---|---|---|---|
| M1 | Security | **No Host-header validation** on the local API, which leaves DNS rebinding possible: a malicious web page can rebind its domain to `127.0.0.1` and read API responses. The data is public, but this becomes serious once private strategies exist. | Probe P9 (`Host: attacker.example` → 200) |
| M2 | Security/Flow | **Cross-origin requests still trigger work.** There's no CORS policy (fine for reads), but any website can fire simple GETs that each cause a Binance request. Combined with no caching or rate limit, that is an amplification path toward a Binance 429/418 IP ban. | Probe P10 |
| M3 | Flow | **No rate-limit handling.** HTTP 429/418 and `Retry-After` are collapsed into a generic error, and the monitor retries at a fixed interval with no backoff or jitter. | `provider.py:51`, `cli.py:55-62` |
| M4 | Flow | **Wrong status code.** Bad upstream data (unordered bars) reaches the API as a `ValueError` and comes back as **422** (client error) instead of 502/503. | Probe P11 |
| M5 | Correctness | **ATR convention unstated.** `atr14` is a simple 14-bar mean of true range, not Wilder's smoothing (probe: 0.00108168 vs 0.00108317). PRD F02 requires stated conventions. | Probe P4 |
| M6 | Data | **Instrument identity missing.** There's no venue, market type (perpetual vs spot) or contract metadata on candles or reports (F01). | Read |
| M7 | Flow | **Per-request timeout, not total.** `urlopen(timeout=8)` limits each socket operation, so a slow-drip response can exceed 8 s overall. The 2 MB read cap is good. | `provider.py:38` |
| M8 | Supply chain/CI | **Weak CI and dependency pinning.** CI tests only Python 3.13, actions are not SHA-pinned, there's no `permissions:` block, and there's no lockfile (`fastapi>=0.115,<1` resolved to 0.162). | `ci.yml` |

### Low

- L1: `Candle.from_binance` silently truncates float timestamps (`int(1.7e12+0.9)`). Probe P7.
- L2: The DSL `==` on floats is fragile (`0.1+0.2 == 0.3` → `NO_MATCH`). Probe P8. Restrict `==`/`!=` or use a tolerance.
- L3: Rules have no version, units, timeframe binding or bar-finality semantics (F05).
- L4: The `WATCH` observation label reads like an action. Prefer explicit `NO_EVENT` / applicability states.
- L5: `assert len(PROFILES) == 20` disappears under `python -O`.
- L6: The package name `trading_intelligence` doesn't match the product/repo name `my-ai-trading`.

### Sound and worth keeping

- Strict OHLC/finite/positive validation and strict ordering/duplicate rejection.
- No-look-ahead breakout logic: the volume ratio and prior high use *prior* bars only.
- A fixed upstream host with an allowlisted symbol/interval (no SSRF surface), a bounded response size, and error messages without secrets.
- A safe JSON rule DSL: allowlisted metrics/operators, node and depth budgets, three-valued logic, no `eval`.
- Zero runtime dependencies for the core; the API is an optional extra.

## 3. Integration plan (smallest safe path)

Single implementer on `feature/fast-engine`, read-only review after each step. Each step is a separate commit with its own tests.

1. **Packaging.** Import into `src/my_ai_trading/`, keeping stdlib-only core and `[api]`/`[test]` extras. Add `.venv` instructions, CI on 3.11 + 3.14 with SHA-pinned actions and `permissions: contents: read`.
2. **Domain types.** Add `InstrumentIdentity` (venue, symbol, market type), a `Timeframe` value object with bar duration, and `Candle` with an explicit `is_closed`. Fix H1 by using server time plus a safety margin. Fix L1.
3. **Series validation.** Add a `CandleSeries` validator for spacing, gaps and duplicates (H2, H3); gaps return `INSUFFICIENT_DATA` with `missing_inputs`.
4. **Fast Engine.** Name the ATR convention (`atr14_sma_tr`), add Wilder ATR, and make indicator warm-up explicit. Remove the auto-applied preset from `analyze()` (H4).
5. **Strategy registry.** Add F13 metadata for all 20 profiles, the applicability gate and statuses, and the Minervini-inspired screen as `experimental` with a `partial` status (H5, H6). Add tests for Scenarios G, H, K and L.
6. **API hardening.** Add a Host allowlist (M1), a short-TTL shared cache plus rate limit on provider calls (M2), 429/`Retry-After` handling and bounded backoff with jitter (M3), and 502/503 mapping (M4).

R2+ (WebSocket monitor, Strategy Studio, copilot, extension, backtesting) builds on these interfaces and is tracked in [`../ROADMAP.md`](../ROADMAP.md).
